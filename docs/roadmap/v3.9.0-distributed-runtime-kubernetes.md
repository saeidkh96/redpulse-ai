# v3.9.0 — Distributed Runtime & Kubernetes

## Goal

Validate RedPulse runtime behavior across multiple independent worker processes and Kubernetes replicas sharing durable infrastructure.

## Scope

- Multi-process worker execution
- Shared PostgreSQL runtime state
- Shared Redis where appropriate
- Kubernetes manifests
- Helm deployment validation
- Worker replicas
- Graceful shutdown
- SIGTERM handling
- Pod restart recovery
- Readiness and liveness probes
- Resource requests and limits
- Rolling updates
- Lease contention under multiple replicas
- Distributed ownership validation
- Deployment-level smoke tests

## Validation Targets

- Multiple replicas competing for the same execution
- Pod termination during active work
- Replacement pod recovers stale work
- Rolling update without corrupting execution ownership
- Readiness prevents traffic before dependencies are available
- Graceful shutdown releases or safely abandons work

## Exit Criteria

- Reproducible local Kubernetes deployment
- Helm-based deployment path
- Multi-replica tests
- Recovery behavior documented
- No claim of production deployment without evidence
