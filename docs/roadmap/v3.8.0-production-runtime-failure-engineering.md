# v3.8.0 — Production Runtime & Failure Engineering

## Goal

Turn the durable runtime mechanisms introduced in v3.7.1 into a failure-tested execution layer that is validated against real process interruption and infrastructure faults.

## Scope

- Real worker process termination and restart tests
- Recovery of expired durable RUNNING executions
- External side-effect idempotency strategy
- Transactional outbox pattern
- Dead-letter execution handling
- Retry classification
- Exponential backoff with jitter
- Retry budgets and terminal failure policies
- Database interruption/recovery tests
- Failure injection utilities
- Runtime recovery metrics
- Recovery-latency measurement
- Explicit documentation of guarantees and non-guarantees

## Validation Targets

- Kill a worker process while it owns an execution
- Confirm another process can recover the work after lease expiry
- Confirm stale owner cannot overwrite the recovered result
- Confirm retry state survives process reconstruction
- Confirm outbox records survive application failure
- Confirm duplicate delivery does not duplicate idempotent side effects
- Confirm permanent failures enter a dead-letter state
- Confirm transient failures respect retry/backoff policy

## Reliability Boundary

The runtime may provide durable ownership, stale-worker recovery, replay control, and fencing. It must not claim exactly-once execution of arbitrary external side effects unless the downstream operation itself supports a compatible idempotency or fencing mechanism.

## Exit Criteria

- Dedicated process-level crash tests
- Failure-injection integration tests
- Metrics for retries, takeovers, dead letters, and recovery time
- Full test suite green
- Updated architecture and reliability documentation
